# Автотесты на устройствах (Maestro)

Релизная сборка (`.dev`, см. память «release-test-install») на обоих устройствах, эмулятор — звонящий
(аккаунт без ника, друг `Ron`), A35 — принимающий (`Ron`). Maestro: `~/.maestro/maestro/bin/maestro`
(2.11.0, архив с GitHub).

Звонки, видео, «пузырь», системный PiP, звук, камера и 5 минут с выключенными экранами — около 17 минут:

```
CALLER=emulator-5554 CALLEE=RFCX306PWLE FRIEND=Ron frontend/e2e/call-matrix.sh
```

Только регрессия звонка с выключенными экранами на двух телефонах:

```
CALLER=R5GL550T4TB CALLEE=RFCX306PWLE FRIEND=Ron frontend/e2e/call-matrix.sh screen_off_audio_5m
```

Отдельные сценарии — именами через пробел (список в начале `call-matrix.sh`).

Перед проверкой звука на громкой связи включите кнопку «Громкий» / «Loud» на обоих
экранах и убедитесь, что речь слышна в обе стороны. У эмулятора Android может показывать
маршрут `speaker`, даже когда кнопка ещё не включена: разговорного динамика у него нет.
Проверьте также разговорную громкость Android и громкость компьютера.

Проверка блокировки контролирует фактический `mScreenState=OFF`; Samsung при этом
может оставаться в `mWakefulness=Dozing`. Служба, wake lock и режим связи подтверждают
жизненный цикл звонка, но не слышимость: дополнительно контролируйте аудиосчётчики
записи/воспроизведения, передачу RTP и реальный звук в обе стороны.

Запуск и вкладки; сообщение с эмулятора приходит на A35:

```
cd frontend
M=~/.maestro/maestro/bin/maestro; TXT="e2e-$(date +%H%M%S)"
$M --device emulator-5554 test e2e/flows/smoke.yaml
$M --device emulator-5554 test -e FRIEND=Ron -e TEXT="$TXT" e2e/flows/chat-send.yaml
$M --device RFCX306PWLE test -e TEXT="$TXT" e2e/flows/chat-received.yaml
```

Тексты в сценариях — regex на двух языках (эмулятор EN, телефоны RU). Полный экран звонка узнаём по
кнопке `minimize`: «Завершить» есть и у «пузыря». Нужные `testID`: `friend-row-call`, `friend-row-chat`,
`chat-input`, `chat-send`, `pip-expand`, `pip-end`.

Перед отправкой и звонком `chat-open.yaml` выбирает кнопку внутри карточки
`friend-card-<userId>` с нужным именем и проверяет `chat-peer-name`. Одного
`rightOf` недостаточно: кнопки других строк тоже находятся правее имени.
Переходы из системного PiP проверяются отдельно: `assert-in-app-pip.yaml`
сохраняет внутреннюю плашку, `assert-full-call.yaml` требует полный экран.

Меню и выбор сообщений: открыть тестовый чат, оставить видимыми два своих текстовых
сообщения и закрыть клавиатуру. Из корня репозитория подставить их тексты и serial устройства:

```
~/.maestro/maestro/bin/maestro --device RFCX306PWLE test \
  -e MESSAGE=menu-test-A-1030 -e SECOND_MESSAGE=menu-test-B-1030 \
  frontend/e2e/flows/chat-message-actions.yaml
```

Сценарий проверяет короткое нажатие → меню, двойное → полоса реакций,
зажатие → сразу отмеченное сообщение и чекбоксы. Затем — выбор второго сообщения,
снятие отметок, пустой выбор, отмену пересылки/удаления, выход по «Назад» и
вход в выбор через пункт меню. Удаление в этом сценарии отменяется; фактическую
пересылку и удаление тестовых сообщений проверять отдельно с получателем.
