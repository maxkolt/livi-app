# Fliq и рамки: ограничения кэшей — 24 ноября 2026

Подтверждены и устранены неограниченные RAM-кэши коротких ссылок/метаданных Fliq и подсказок рамок пользователей. Также найдена проверка срока метаданных только на диске: однажды загруженное в RAM превью могло пережить свой срок годности. Новая утечка по снимкам кучи в этой задаче не устанавливалась.

## Ограничения

| Данные | Записи / задачи | Бюджет оценки строк | Срок |
| --- | ---: | ---: | --- |
| Разрешённые короткие ссылки | 128 | 128 КиБ | 30 минут; неподдерживаемый результат — 30 секунд |
| Метаданные карточек Fliq | 128 | 512 КиБ | До 30 минут, с учётом оставшегося срока дисковой записи |
| Подсказки рамок | 256 | 64 КиБ | 30 минут |
| Запросы метаданных | 24 всего, одновременно 4 | 64 КиБ ключей/исходных ссылок | 15 секунд от постановки |
| Запросы редиректов | 8 всего, одновременно 2 | 64 КиБ ссылок | 15 секунд от постановки |

Используется существующий LRU с таймером удаления без следующих чтений. Оценки учитывают UTF-16 строки и небольшой фиксированный запас, а не всю память объектов/процесса. Большой ответ по-прежнему передаётся потребителю полностью, но не остаётся в RAM-кэше; метаданные больше 512 КиБ по этой оценке также не записываются на диск.

Дисковый срок метаданных сохранён: YouTube/Instagram — 7 дней, TikTok — 12 часов. При переносе с диска в RAM срок не начинается заново. Неудачные метаданные не удерживаются на всю сессию. Сигнал нехватки памяти очищает готовые кэши Fliq; результат уже запущенного ограниченного запроса остаётся доступен потребителю, но не восстанавливает очищенный RAM-кэш.

Очереди ограничивают и чтение AsyncStorage, и HTTP, и ожидание JSON. Существующий HTTP abort через 8 секунд сохранён; общий 15-секундный дедлайн также ограничивает потребителя при зависшем чтении/JSON, даже если abort не завершил операцию. Незавершённые операции продолжают занимать свои слоты и бюджет, поэтому повторные запросы не создают неограниченное число нативных операций. Поздний результат не публикуется после таймаута.

При занятой очереди видимая карточка повторяет запрос с растущим интервалом до 15 секунд. Повторы прекращаются при размонтировании или смене ссылки; глобального списка ожидания карточек нет. На первом рендере новой ссылки предыдущие название/превью исключаются по идентичности, поздний ответ старой ссылки игнорируется.

Подсказки рамок отделены от прав владения, кошелька, выбранного оформления и состояния смонтированного хука. Вытеснение не удаляет покупки и не снимает уже показанную рамку. Сохранение подсказок на диск также ограничено текущими 256 записями. Старый снимок с тысячами подсказок переписывается ограниченным; собственное оформление и покупки сохраняются. Небольшой кэш рамок не сбрасывается по memory pressure: он ограничен 64 КиБ и освобождается по TTL/LRU, не добавляя пропадания рамок при перемонтировании.

## Проверки

- Полная серия frontend: **194 набора / 1793 теста PASS**.
- TypeScript, ESLint затронутых исходников/тестов и `git diff --check`: **PASS**.
- Добавлено 17 проверок: LRU, объём строк, срок подписанного превью, восстановление с диска, переполнение, зависшие fetch/JSON, поздние результаты, memory pressure, смена ссылки, отмена повторов, миграция большого снимка рамок и сохранность покупок/кошелька. Существующие тесты авторизации, изменения косметики и восстановления при смене сети также прошли.

На единственном подключённом Samsung A35 (`RFCX306PWLE`) проверен актуальный JS в dev-сборке:

- Из одновременных 100 запросов метаданных допущены 24, одновременно работали максимум 4. Остальные получили отказ очереди; повтор для видимой карточки покрыт компонентным автотестом.
- Обработаны 300 разных синтетических метаданных. RAM удерживала 128 записей, после memory pressure — ноль. Последняя запись восстановилась с AsyncStorage: число HTTP-запросов осталось `300 → 300`.
- Проверены 140 коротких ссылок через настоящий Android HTTP с локальным редиректом. Горячая ссылка не делала нового запроса, вытесненная снова разрешалась успешно. Для проверки parser итоговый локальный URL преобразован тестовой обёрткой в фиксированный TikTok URL.
- После 1000 тестовых обновлений рамок RAM и сохранённый снимок удерживали 256 подсказок. Снимок собственных покупок/оформления, прочитанный штатным API до и после, совпал. Серверные операции покупки/применения/удаления не выполнялись.
- Физически проверено истечение оставшихся 1,5 секунды TikTok-метаданных с диска и одно последующее обновление.
- Для таймаута выдача уже полученного JSON задерживалась временной JS-обёрткой на 16,5 секунды. Production-дедлайн сработал через **15 008 мс**, pending стал равен нулю, операция сохраняла один слот до завершения. Поздние метаданные не попали в RAM, повторный запрос сработал. Это моделирование задержанного JSON, а не доказательство реального зависания native fetch.
- PID сохранился (`10115 → 10115`). В конце обе очереди имеют active/pending = 0. Временные функции восстановлены, тестовые ключи удалены либо восстановлены из точной резервной копии, исходный снимок косметики и RAM-подсказки восстановлены. Настройка удержания экрана возвращена к исходной `0`.

Для синтетических запросов использован локальный HTTP-сервер через USB; запросы прочей функциональности шли штатным fetch. Этот тест не подтверждает работу внешних TikTok/YouTube или полного плеера с VPN/без VPN. Release/AAB не пересобирался; перед публикацией остаётся прогон нового release-кандидата на A35. Общая JS/native/GPU память и полная визуальная регрессия приложения в этой задаче не измерялись. Количество старых ключей метаданных Fliq на диске не сокращалось: изменены RAM-кэши и верхняя граница одной новой дисковой записи.
