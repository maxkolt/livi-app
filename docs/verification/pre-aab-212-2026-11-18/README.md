# Проверка перед AAB 212 — 17–18 ноября 2026

Позднее 18.11.2026 выполнена отдельная [подготовка безопасности и обновление backend](../security-release-ready-2026-11-18/README.md).
Фактический сброс production и строгий новый старт ещё не активированы.

Проверены и исправлены два конкретных дефекта: перехват фокуса после удалённого
завершения звонка в системном PiP и отсутствие принятого входящего в переписке,
если при вызове чат был закрыт. Полная готовность публикуемого AAB этим отчётом
не подтверждается: использовался отдельный standalone QA APK.

## Изменения

- `terminateCall(call_ended_surfaces)` закрывает поверхности с `skipMainReturn`.
  Нативный код возвращает Main после закрытия исходящего только когда действительно
  существовала OutgoingCallActivity. Обычная локальная отмена исходящего сохраняет
  прежний путь возврата.
- Программное закрытие системного PiP после конца звонка отдельно помечено в MainActivity:
  оно не порождает ложные события пользовательского разворачивания или нажатия X.
- Принятые входящие и исходящие сохраняют локальное облако в переписке независимо
  от открытого экрана. Идентификатор звонка входит в идентификатор облака, поэтому
  повторная доставка принятия не добавляет второе сообщение. Старые отсутствующие
  облака автоматически не восстанавливаются; серверная история сообщений не менялась.
- Для входа в PiP убрана подсказка `sourceRectHint`, заставлявшая Android масштабировать
  старый кадр с кнопками. Теперь включается системный слой с иконкой LiVi; имеющаяся
  нативная заглушка защищает содержимое до готовности чистого видеослоя. Автоматический
  вход сохранён. Это улучшение покрытия перехода, а не доказательство отсутствия
  кнопок во всей начальной фазе анимации.

## Автоматические проверки

- Frontend: **145 наборов, 1393 теста**, все прошли.
- ESLint frontend/backend и frontend TypeScript: прошли. Backend TypeScript также
  проходил до этих клиентских изменений; backend-код в этой проверке не менялся.
- Kotlin/JVM: **18 тестов**, все прошли.
- Release QA APK: Hermes bundle внутри APK, production API, R8, arm64.
  Отдельный пакет `com.kolt12max.livi.dev`, тестовая подпись, `BuildConfig.DEBUG=false`.
  Загрузка Crashlytics mapping исключена. Это не публикуемый артефакт.
- Регрессии проверяют удалённый конец/обычную отмену исходящего, входящий при закрытом
  чате, повторное принятие после истечения временного дедупа и принятый исходящий
  вне открытой переписки. Тест сохранения использует настоящие callLog,
  chatCallEvents и messageStorage с заменой только AsyncStorage/внешних событий.

## Открытые пункты

1. **Переходный кадр PiP.** В короткой анимации Samsung виден уменьшающийся снимок
   полного интерфейса с кнопками, затем защитный слой и видео. После удаления
   `sourceRectHint` появился системный слой с иконкой LiVi, но начало анимации ещё
   содержит старый кадр. Ранний обработчик Android 15+, обрезка sourceRect и показ
   заглушки при потере фокуса не обеспечили полного устранения и удалены. QA вариант
   ожидания отрисовки перед входом нарушил PiP на A35 (`Activity must be resumed`),
   также удалён; автоматический вход восстановлен и повторно прошёл на обоих.
   Пользователь вновь подтвердил двусторонние звук и видео, обе камеры до перехода
   отдельно проверены в Active Camera Clients. Полностью чистый переход не заявляется
   исправленным.
2. **Публикуемый AAB 212:** собрать подписанный кандидат, проверить APK, полученные
   именно из него/через Play, и повторить короткую проверку звонка, PiP, голосового
   и Bluetooth. QA APK не заменяет эту проверку.
3. **Приглашение через Google Play:** установка нового пользователя по реальной
   ссылке через магазин и сохранение referrer после установки ещё не проверены
   на публикуемом кандидате.
4. **Версия сервера:** ранее сервер объявлял 211. В этой работе публикация версии
   и серверный деплой не выполнялись.
5. В процессе были нефатальные сетевые EOF/SSL ошибки загрузки изображений Skia.
   Источник каждого исторического сообщения не доказан; отсутствие всех таких
   ошибок и отсутствие любых сбоев приложения не заявляются.

Подготовка свежего старта аккаунтов/строгой авторизации оставлена без изменений.
MongoDB не очищалась, режим безопасности и production backend не переключались.
Проверка завершена: оба телефона в MODE_NORMAL, камеры освобождены, служб звонка,
pinned task и call wakelock нет. Исходный stay-on режим восстановлен (A35: 0, S25: 2).
Основной Play-пакет не обновлялся. AAB не создавался, commit/push не выполнялись.
