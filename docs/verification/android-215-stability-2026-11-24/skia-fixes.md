# Skia 2.2.4: владение Promise, загрузчик Android и FliqAmbient

Исправления от 24 ноября 2026. Зависимость остаётся на 2.2.4; патч сохраняется в `frontend/patches/react-native-skia+2.2.4-promises.patch` и применяется через postinstall. Изменение только в node_modules не требуется повторять вручную.

## Владение runtime

JS-функции resolve/reject находятся в реестре HostObject, принадлежащем global своего runtime. Нативный Promise содержит только weak_ptr реестра и идентификатор запроса. Фоновые задачи и очереди передают нативные данные и такой идентификатор; Runtime и JSI-значения не захватываются.

Создание JSI-результата выполняется фабрикой на исходной JS-очереди, после проверки реестра и запроса. Завершённая запись удаляется перед вызовом JS. Повторные завершения и ответы после уничтожения runtime игнорируются; удаление callback из очереди также не уничтожает JSI-объекты в worker. Правило действует для `Data.fromURI`, `MakeImageFromViewTag` и `makeImageSnapshotAsync`. Для отсутствующего Canvas добавлен reject вместо разыменования null.

Основание: [контракт JSI React Native 0.79.6](https://raw.githubusercontent.com/facebook/react-native/v0.79.6/packages/react-native/ReactCommon/jsi/jsi/jsi.h), включая разрешённое освобождение JSI-объектов деструктором HostObject во время завершения runtime. Resolve/reject нативного идентификатора по-прежнему должны вызываться только на исходной JS-очереди.

## Android

- Все результаты чтения доходят до единственного callback: ошибка, null, пустой массив и отказ выделения памяти передают null-поток, который приводит к reject на живом runtime.
- Загрузчик держит Java peer через global_ref, без сырого `this`. Java owner и захваты callback освобождаются до отсоединения worker от JVM.
- Копирование через `GetByteArrayRegion` убирает ручной malloc, закреплённый Java-массив и отдельную необёрнутую JNI-строку.
- Java закрывает сетевые и ресурсные потоки через try-with-resources и отключает HttpURLConnection в finally. Чтение использует то же соединение, которому настроены connect/read timeout по 15 секунд.
- Во время чтения проверяется 30-секундный бюджет. Это дополнительная проверка между чтениями, а не строгий общий дедлайн DNS, соединения и всего запроса.
- Null/пустые данные проверяются до создания JSI Data и декодирования изображения.
- Физический тест дополнительно обнаружил uncaught JNI exception при снимке View с RuntimeShader: software Canvas не поддерживает такой shader. Добавлен перехват ошибки с reject, проверка null/размеров/результата блокировки Bitmap, RAII для JNI local reference и unlock pixels. Отсутствующий View также отклоняется без dev error screen. Успешный снимок сложного View с RuntimeShader этим изменением не реализован.

## Fliq

Скрытая/неактивная вкладка, отсутствие URL/ресурсов или нулевой размер размонтируют поддерево, владеющее состоянием изображений. Прежний кадр удаляется после завершения 300-мс перехода; старые completion callback проверяют поколение перехода. Ошибка нового превью убирает оставшийся свет предыдущего ролика.

Кэш ограничен шестью записями и 6 MiB по оценке RGBA `width × height × 4`. Это бюджет кэша, не измерение всей native/GPU RAM. Работают не более двух нативных загрузок и восьми ожидающих запросов суммарно. Видимый запрос получает приоритет перед предзагрузкой; скрытая лента не запускает новую предзагрузку.

Через 45 секунд запрос удаляется из pending, его подписчики освобождаются. Отмена компонента также удаляет его callback. Истёкший запрос сохраняет занятый слот до фактического завершения нативной операции: логический таймаут не разрешает бесконечно создавать новые нативные загрузчики. Поздние данные не декодируются, поздние непереданные изображения освобождаются. Memory pressure инвалидирует поколения и очищает кэш.

SkData освобождается после попытки декодирования. Непереданные рендереру изображения освобождаются явно при вытеснении. После передачи изображения потребителю кэш освобождает только свою ссылку: общий JSI wrapper и native recordings завершают жизнь со своими последними владельцами. Принудительный dispose общего изображения не вызывается.

## Проверки

- `npm --prefix frontend run test:ci`: 182 набора / 1728 тестов, включая 18 новых тестов Fliq.
- TypeScript frontend, ESLint frontend/backend, `git diff --check` и синтаксис скриптов.
- `npm --prefix frontend run test:skia:native`: свежая/повторная установка патча, отказ при несовместимой зависимости и отсутствии патча, отсутствие частичных изменений.
- Настоящий JSI/JSC с ASan/UBSan: успех, reject, повторное завершение, ошибки setup/фабрики, 100 уничтожений runtime с поздними ответами и уничтожением нативного идентификатора в worker. Драйвер требует macOS/Xcode.
- Production Java-код загрузчика на JDK 17 с инструментированными Android-ресурсами и URLConnection: успешный/пустой ответ, ошибка чтения, имитация ошибки таймаута, некорректный URI, закрытие ресурсов, disconnect и одно соединение с настроенными таймаутами. Это не проверка реальной сети Android.
- Android Java и native arm64 успешно собраны; полный `:app:assembleDebug -PreactNativeArchitectures=arm64-v8a --offline` прошёл. APK: `frontend/android/app/build/outputs/apk/debug/app-debug.apk`, SHA-256 `f57baa87ab410d1d9bbeef1a5bb7d7461848c734df911b0bb3ceba25d25efe76`.

## Физические устройства и ограничения

Первоначальное подключение A35 к Metro не удалось. В последующей сессии Metro/Hermes заработали на обоих телефонах; выполнен отдельный повторный прогон после окончания ручных переключений пользователя. Итоги и ограничения: [skia-device-checks.md](./skia-device-checks.md).

На A35 VPN не включался. На S25 Ultra использован установленный VPN «Привата» (`com.privatasolutions.vpn`), активность подтверждена Android network agent и диапазоном UID. Устройства получили один APK, SHA-256 установленного файла совпал с локальным.

Signed AAB с исправлением не собирался; существующий AAB 215 относится к состоянию до патча. Release lifecycle и длительные измерения native/GPU RAM не проверялись. Результаты кэша относятся к его собственным ссылкам и оценке байтов, а не ко всей памяти процесса.
