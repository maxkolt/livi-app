Одновременные замеры системных часов показали отличие S25 и A35 около 0.12 с, поэтому оно не объясняет секундные задержки. Во втором случае между emit на одном телефоне и обработчиком event на другом также около 3.5 с: имеющиеся журналы не разделяют сетевую доставку, работу сервера и очередь JS на получателе, и эта часть не объявлена установленным дефектом сервера/сети.

Принимающий показывает UI по локальному нажатию, не ожидая сервер. Звонящий узнаёт об ответе из подтверждения сервера. В коде до каждого accept выполнялся await динамического импорта/проверки reauth даже при свежем подтверждении владения этим соединением; продолжение могло выполняться после тяжёлого mount VideoCall. Код позволяет установить наличие лишней асинхронной границы, но без дополнительных phase-замеров нельзя всю begin→emit задержку приписать только ей.

## Правка

- Авторизация и ключ для входящего подготавливаются во время ringing как для socket-события, так и для общего обработчика native incoming.
- При уже готовом ключе и свежем подтверждении владения тем же socket ID и user ID call:accept отправляется синхронно до передачи управления mount экрана.
- Срок свежести авторизации 6 с сохранён. При смене соединения/пользователя, disconnect, истечении срока и отказе сервера требуется обычный reauth/retry. Шифрование не отключается, ключи не заменяются произвольно.
- У инициатора навигация/снятие native outgoing под защитным фоном выполняются перед prewarm аудио/ICE и ранним созданием медиасессии. Готовность комнаты по-прежнему не является условием показа интерфейса.
- Добавлены phase call_accept_auth_ready / call_accept_key_ready с признаком использования подготовленного состояния для следующего физического прогона.

## Проверки и пределы

Все frontend-проверки: 179 suites / 1708 tests PASS, TypeScript и ESLint PASS. В том числе новый тест проверяет вызов emit до первого microtask, отдельные тесты сохраняют запрет accept без подтверждения владения и отклоняют proof другого пользователя, другого/отключённого соединения, истёкший и будущий timestamp. Prewarm-тест подтверждает, что сама подготовка не принимает звонок.

Свежие AAB/APK, установленные хеши и результаты валидации — results.json. Физическая повторная проверка этой оптимизации ожидается. Время после исправления не измерено; тесты не доказывают устранение сетевой части задержки или мгновенный переход на обоих телефонах.

Просмотрены кадры обеих записей исходного прогона, отобран участок 44–80 с с шагом 0.1 с: видны нативный исходящий и последующий настоящий audio UI в состоянии «Соединение». Поиск прежнего центрального голубого логотипа на этом участке не дал кандидатов; выборочные кадры проверены визуально. Это ограниченная проверка записи (10 fps), а не гарантия отсутствия любого однокадрового артефакта во всех режимах.
