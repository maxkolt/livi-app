# Шрифты Search, нижний отступ и тестовая заявка

22 ноября 2026. Продолжение проверки A35 с навигацией жестами и S25 с тремя системными кнопками. Только dev-сборка 214 через Metro; релизный APK/AAB в этой работе не пересобран.

## Причина изменения шрифта

В Android ReactTextShadowNode автоподбор (`adjustsFontSizeToFit`) изменяет размер ReactAbsoluteSizeSpan в подготовленном тексте. При возврате из узкого PiP этот размер может сохраниться. В исходном состоянии A35 для «Найти собеседника» прочитаны заданный `mFontSize=45 px`, фактический span `31 px`. Размер окна в тот момент уже полный: 411.43 × 891.43 dp, системный fontScale=1.

AdaptiveText уже пересоздавал native Text при смене ширины Dimensions. Этого недостаточно: размеры Home приходят позже, и новый Text мог снова измериться в ещё узком контейнере. CTA теперь пересоздаёт FitText при смене своей конечной ширины/высоты; блок «Онлайн» пересоздаёт только текстовую колонку при смене ширины Home или режима компактности. Фикс не меняет заданные размеры шрифта и сохраняет автоподбор для длинных переводов.

После обновления CTA фактический span вновь 45 px, как заданный размер. Оба текста панели «Онлайн» включены в повторную физическую проверку.

## Нижний отступ

В общей геометрии Home dock добавлены 20 dp снизу для Android в обычной раскладке при нижнем системном inset <= 24 dp. Сначала добавка составляла 12 dp; по двум следующим просьбам пользователя панель поднята ещё дважды на 4 dp (12 → 16 → 20 dp). Это покрывает малый inset жестов и скрытый маркер. Полная кнопочная панель с большим inset, компактная горизонтальная раскладка и iOS сохраняют прежний базовый расчёт. На этом этапе менялся только нижний отступ; следующая правка размеров описана ниже. Старые снимки относятся к первоначальной добавке 12 dp.

## Панель и CTA на A35 и меньших экранах

В портрете для существующего класса A35/меньших телефонов нижний зазор увеличен ещё на 8 dp. Высота основного блока навигации теперь совпадает с панелью «Онлайн»: 78 dp, на коротких окнах менее 700 dp — 66 dp. Боковые поля уже совпадали (12 dp); ряд иконок отцентрирован в новой высоте. Изгиб над Fliq сохранён. S25 Ultra, планшеты и горизонтальная навигация сохраняют прежние размеры. Класс учитывает модель и плотность, поэтому увеличение масштаба дисплея S25 не включает вариант A35.

Кнопке «Найти собеседника» добавлен подъём на 8 dp. Дополнительно устранено расхождение оценки свободной высоты Search: раньше она не учитывала добавленные 20 dp под навигацией и отклоняла фактический замер контейнера. Теперь Home, Search и сама панель используют `welcomeTabBarMetrics`; общий фактический подъём CTA включает исправление этого расчёта и новый размер панели.

На физическом A35 с жестами и окном 411,43 × 891,43 dp проверен экран поиска после загрузки текущего кода из Metro: панель выше, ширина совпадает с «Онлайн», высота основного блока визуально соответствует верхней панели; CTA выше и не пересекает ник или навигацию. Runtime подтвердил `contentHeight=78`, `bottomGap=52`, `ctaLift=8`; системный fontScale=1. Снимки: `/private/tmp/livi-search-font-20261122/nav-next-before.png` и `nav-sized-a35-ready.png`. Числа в dp — параметры раскладки, а не независимый пиксельный замер снимков.

Проверки этой правки: 3 suites / 36 tests PASS (`welcomeTabBarLayout`, `phoneAvatarLayout`, `searchRadarPlacement`), frontend TypeScript, ESLint изменённых файлов и `git diff --check` PASS. В тестах покрыты масштабы A35/S25, короткий экран, жесты/системные кнопки, планшет и landscape. Меньшие физические телефоны отдельно не проверялись.

## Тестовая заявка

В `store/friendRequests.ts` найдена синтетическая «Тестовая заявка», которая добавлялась кодом при `__DEV__`. Удалены её генерация и имитация ответа. Служебный ID старого макета отфильтровывается из кэша, серверного снимка и realtime-обновлений; ответы по нему не отправляются на сервер. Настоящие заявки и обработка принятия сохранены. Производственные аккаунты не удалялись.

## Проверки и ограничения

Целевые проверки: 7 suites / 52 tests PASS; frontend TypeScript и ESLint изменённых файлов PASS; git diff --check PASS. Проверяются пустой список без фикстуры после повторной инициализации, старый offline-кэш с настоящей заявкой, server/realtime-фильтрация, запрет фиктивных ответов, принятие настоящей заявки и варианты нижних системных отступов.

Видеопрогон снова показал ранее найденный неправильный capture/return PiP; этот дефект не исправлен правкой типографики. В конце длительной dev-сессии оба процесса получили native SIGSEGV: S25 в 13:46:45, A35 в 13:46:53 по часам устройств. На A35 верх стека — librnskia.so / RNJsi::JsiPromises::Promise destruction. До этого выполнялись перезагрузки JS и диагностика. Причинная связь с текущими правками не установлена; стабильность релиза и устранение сбоя не заявляются. Журналы сохранены, приложения запущены заново для отдельной проверки аудио-PiP.

Сырые данные: `/private/tmp/livi-search-font-20261122/`: `text-initial.txt`, `text-after-cta-key.txt`, `ready-native.txt`, `baseline-patched-a35.png`, `ready-s25.png`, `exit-info.txt`, `exit-info-s25.txt`, `crash-buffer.txt`, `tests.log`, `typecheck.log`, `lint.log`. ## Финальный повтор после перезапуска

Отдельный обычный звонок с S25 на Max принят на A35. Полный экран → жест Назад → аудиопанель in-app PiP → короткий свайп снизу → system PiP → открытие MainActivity. Сравнение Android TextView до и после этого цикла прошло автоматически: CTA 45/45 px (задан/фактически), «Онлайн» 45/45 px, счётчик 31/31 px. Данные — `font-verification.json`, `fresh-baseline-native.txt`, `fresh-after-pip-native.txt`, снимки `fresh-audio-inapp-before.png` и `fresh-audio-inapp-after.png`. Этот положительный результат относится к типографике и аудио-PiP; ранее отмеченный отказ захвата/возврата видеозвонка остаётся открытым.

Итоговая очистка обоих телефонов: MODE_NORMAL, Active Camera Clients = [], нет входящего/активного call service, pinned LiVi и LiVi wake locks. A35 оставлен с жестами, S25 — с тремя кнопками. Данные — `cleanup.json` в том же временном каталоге.

Страница «Заявки в друзья» открыта на A35 после обновления: синтетической «Тестовой заявки» нет. Свежая UIAutomator-иерархия `requests.xml` проверена на отсутствие этой строки, итоговый снимок — `requests-no-fixture-final.png`.
