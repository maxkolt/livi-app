# A35: навигация жестами и PiP, 22 ноября 2026

Проверка по запросу пользователя: исходящие с S25 Ultra SM-S938B (`R5GL550T4TB`), принимающий и проверяемый A35 SM-A356E (`RFCX306PWLE`). На обоих — установленная LiVi Dev 214 / 1.1.23 через Metro. A35 — Android 17, S25 — Android 16. Результат относится к dev-сборке; standalone release в этой проверке не устанавливался.

На A35 в системных настройках выбраны «Жесты проведения», `navigation_bar_gesture_while_hidden=1`, маркер навигации оставлен видимым. Три кнопки скрыты. Для «Назад» использован свайп от левого края, для ухода на главный экран — свайп снизу. Samsung классифицировал нижний свайп как `recentapps`, после которого код приложения запускал системный PiP. Разворот системного PiP автоматизирован открытием MainActivity; системная кнопка разворота отдельно не проверялась. VPN и сетевые настройки в этом прогоне не переключались.

В начале ошибочно выбран старый тестовый контакт Ron. После уточнения пользователя он больше не использовался; все принятые звонки и дальнейшие проверки — с Max на A35. Подтверждённый входящий экран с Max сохранён.

## Результат

| Сценарий на A35 | Наблюдение |
| --- | --- |
| Обычный звонок, полный экран → жест Назад → in-app PiP | Панель аудиозвонка появилась; после возврата из system PiP панель восстановилась |
| Обычный звонок, полный экран / in-app → нижний свайп → system PiP | Окно с логотипом LiVi; возврат на полный экран и в панель аудиозвонка проверен |
| Видеозвонок, обе камеры, полный экран | Собеседник и локальное превью видны на обоих телефонах |
| Видеозвонок, обе камеры, Назад → in-app PiP | В отдельном повторном звонке видны собеседник, локальный inset и управляющая панель |
| Видеозвонок, полный экран → нижний свайп → system PiP | FAIL: окно остаётся с логотипом вместо видео в зафиксированных снимках |
| Видеозвонок, переходы system PiP / in-app PiP | FAIL: зафиксирован захват интерфейса Home внутри системного окна |
| Возврат из system PiP | FAIL: зафиксирован полный экран с исчезнувшим локальным превью, но оставшейся кнопкой переключения камеры — соответствует третьему скриншоту пользователя; также был кадр видео без обычных элементов экрана |

Эти отказы воспроизведены; код захвата PiP в этой работе не изменён и исправленным не объявляется. Наблюдаемая задержка доставки событий native → JS и расходящиеся флаги — диагностические данные, а не доказанная единственная первопричина. Например, отдельный наблюдатель получил AboutToEnterSystemPiP с traceId `hp_1795343480524` в `1795343483248`, SystemPiPModeChanged(true) в `1795343493179`, false в `1795343502090`. При чтении JDWP окно Android действительно находилось в PiP. Отладчик VM не приостанавливал.

## Кнопки вызова после завершения

На S25 после завершения первого принятого звонка все кнопки вызова в «Друзьях» остались disabled. Чтение runtime показало `active=false`, `ending=false`, `outgoing=false`, отсутствие сессии, `pip=false`, `pending=false`, `params=null`. Переключение вкладок не сняло блокировку.

Причина на уровне UI: кнопки читают runtime refs, но сохранённая вкладка с неизменными props не получает обновление при завершении сессии. `FriendRowInviteButton` теперь подписан на существующий callLifecycle через useSyncExternalStore. После загрузки исправленного JS повторный видеозвонок завершён кнопкой S25: кнопки снова активны, следующий исходящий на Max принят на A35 без перезапуска приложения. Отдельный regression-тест проверяет обновление без изменения parent props для локального/удалённого завершения и сохранение блокировки при активном in-app PiP.

Автопроверки: 4 suites / 26 tests PASS, frontend typecheck PASS, ESLint двух изменённых файлов PASS, git diff --check PASS. Release APK/AAB не пересобирался, commit/push и backend deployment не выполнялись.
