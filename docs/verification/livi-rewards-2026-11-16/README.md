# Legendary: LiVi баллы — 16 ноября 2026

## Правила

- За каждого нового друга по персональной ссылке — 10 LiVi баллов. Фон стоит 50, доступная рамка — 100.
- Приглашённый открывает ссылку в первые 7 дней своего аккаунта и принимает приглашение. Первый пригласивший закрепляется один раз; аккаунт пригласившего должен быть старше. Уже существующая дружба не засчитывается.
- Баллы начисляются при принятии через HTTP или socket, включая отложенное принятие заявки. Удаление и повторное добавление друга не дают повторной награды. Старые приглашения автоматически не пересчитываются.
- За первую обратную связь **внутри LiVi** (20–2000 символов) выдаётся один фон на выбор. Награда не зависит от содержания мнения. Это не отзыв в магазине; публичные оценки не проверяются и не вознаграждаются.
- Обратная связь хранится в `User.feedbackText`, по умолчанию исключена из выборок и не отправляется в косметических API.
- Списания, владение и применение оформления меняются атомарно в одном документе. Повтор запроса не списывает баллы повторно и не восстанавливает потраченный подарок.
- Ранее купленные оформления сохраняются. Новые денежные заказы и открытие старых страниц оплаты отключены (`410 use_livi_points`), проверка и подтверждение ранее оплаченных заказов сохранены.

## Проверки

`LIVI_REWARDS_TEST_MONGO_URI=mongodb://127.0.0.1:27017 npm run check`

Итоговый `npm run check` прошёл: ESLint, TypeScript, 129 frontend-наборов / 1304 теста и 32 backend-набора / 330 тестов (включая 23 новых интеграционных сценария). Production-экспорт Android основного `index.tsx` через Expo прошёл; временный результат вынесен из репозитория в `/tmp/livi-rewards-android-export-2026-11-16`.

Интеграционный набор создаёт отдельную базу `livi_rewards_test_<pid>_<timestamp>` и удаляет её после завершения. Тестирует настоящие MongoDB-запросы и HTTP-маршруты: параллельные начисления/списания, повторные запросы, однократный подарок, сохранение старого владения, атрибуцию, запрет новых денежных заказов и восстановление прерванного начисления. Без переменной этот набор пропускается.

На Samsung A35 (`RFCX306PWLE`) проверен изолированный dev-предпросмотр с тестовыми данными: витрина, подтверждение, смена баланса 50 → 0, приглашения, ввод и отправка обратной связи с клавиатурой, получение подарка, портретная и альбомная ориентации. Серверная логика проверялась отдельно на реальной локальной MongoDB. Предпросмотр не обращался к аккаунтам и платежам; временные entrypoint/config/данные удалены, настройки ориентации восстановлены.

## Выпуск и границы проверки

На момент описанных проверок изменения были подготовлены локально; production backend и магазин приложений ещё не обновлялись. Выпускать сначала backend, затем приложение; проверить индекс `users: { referredBy: 1, referralAccepted: 1 }`. Новые поля не требуют переноса старых покупок. Старые клиенты после обновления сервера не смогут создавать денежные заказы.

Перед выпуском остаётся проверить установку по реальной ссылке через магазин на новом устройстве и связку двух устройств с новым backend, включая VPN и восстановление сети. Защита исключает повторную награду за один аккаунт; она не подтверждает, что за разными новыми аккаунтами стоят разные физические люди. UI наград добавлен на русском и английском; остальные языки используют английский fallback для новых строк.
