# Чат: память и скорость, 24 ноября 2026

Проверены Samsung A35 (SM-A356E / RFCX306PWLE) и S25 Ultra (SM-S938B / R5GL550T4TB), приложение `com.kolt12max.livi.dev`, текущие исходники через Metro/Hermes. Результаты относятся к dev-сборке. Релизный APK/AAB в этой задаче не пересобирались. Уже существовавшие изменения Fliq/Skia сохранены.

## Подтверждено и исправлено

**Голосовые.** На обоих телефонах воспроизведена гонка реальных `Audio.Sound`: первый плеер загружен, остановка задерживается тестовым барьером, запускается второй запрос и чат закрывается. До исправления после снятия барьера создавался второй плеер, оставался `_loaded=true`, владелец `audio:qa-b`. После исправления создан только один плеер, он выгружен, владелец null. Использовался локальный 12-секундный тихий WAV; слышимость настоящего голосового этим тестом не подтверждается.

Поколение запроса фиксируется до ожидания остановки. Закрытие/новый запрос отменяют продолжения после остановки, изменения аудиорежима, загрузки файла и создания звука. Новый звук создаётся с `shouldPlay=false`, затем проверяется актуальность и запускается; поздний звук выгружается. Устаревшие status callbacks игнорируются, ошибка play также выгружает плеер.

**Дополнительная подтверждённая утечка анимаций.** Разрешённые пользователем локальные снимки показали цепочку `AnimatedProps.callback → shared Environment → предыдущий AnimatedProps`. В state-based memo-пути React Native 0.79.6 новый callback создавался в render-окружении, которое сохраняло предыдущий узел. С ним удерживались прошлые React children, анимации и замыкания. Callback вынесен в отдельную фабрику с единственной ссылкой на onUpdateRef. Патч `frontend/patches/react-native+0.79.6-animated-props-retention.patch` обязателен при postinstall и проверяется повторно; несовместимая зависимость останавливает установку вместо молчаливого пропуска.

Просмотрщик и compose-preview теперь размонтируются после завершения анимации закрытия, когда очищается selectedMedia/composeAssets. Скрытые экземпляры больше не удерживают редакторские замыкания. Поздний onClosed не очищает новое открытие фото/compose: это проверено отдельными unit-тестами и контролируемым повторным открытием на обоих телефонах. Узел Animated.multiply для масштаба переиспользуется между рендерами.

**Фото.** Для 40 тестовых файлов JPEG 2048×1536 исходный просмотрщик допускал сразу 42 страницы с учётом двух элементов для зацикливания. После 1,8 с наблюдались 23 компонента изображения на каждом телефоне. Исправленный просмотрщик держит максимум три изображения: текущую страницу и соседние; дальние страницы — пустые View. Ограничены initial/batch/window, включая страницы, которые FlatList может удерживать после первого отображения.

Прогрев чата ограничен шестью недавними изображениями вместо 56. Прогрев просмотрщика ограничен соседними фото. HTTP prefetch использует дисковый кэш; локальные/расшифрованные файлы повторно не декодируются в bitmap только ради прогрева. Полный исходный файл сохраняется, действующее downscaling при отображении сохранено.

**История.** Общий RAM-кэш ограничен восемью чатами и оценкой 4 MiB; слишком большая запись не кэшируется, сами сообщения не обрезаются. Один таймер реально удаляет записи через пять минут без последующих чтений. При нехватке памяти кэш очищается. Нормализация приватных объектов после JSON.parse выполняется за один проход без двух копий каждого сообщения. Регрессия на 10 000 сообщений сохраняет их количество, порядок, время, отправителя и фото-метаданные.

Это ещё не постраничное локальное хранилище: активная переписка читается целиком. Полный переход на локальную пагинацию не выполнен; история не удалялась и не усекалась.

**Вложения.** Таблица разрешённых файлов ограничена 128 записями, бюджетом оценки строк 256 KiB и TTL пять минут. Очередь допускает максимум 24 pending и три нативные операции. Дедлайн 45 секунд освобождает ожидающих, отменяет загрузку и запрещает позднюю публикацию. Пока нативная отмена не завершилась, занятый слот учитывается. У очередей нет растущего неограниченного списка ожидания.

Расшифрованный файл получает стабильное имя, зависящее от владельца, URL и ключа. После вытеснения из RAM он переиспользуется с диска. Неудачные/временные файлы удаляются; смена владельца проверяется после асинхронных границ. Автоматическое удаление всех старых дисковых файлов по размеру не добавлялось: они остаются в Android cacheDirectory и могут быть удалены системой. Кэш обычных старых voice URL также ограничен; прогрев сокращён с 30 до трёх голосовых.

## Два устройства

На каждом телефоне прошли 18 циклов открытия/закрытия ленты из 40 фото, шесть физических свайпов, включая переход 39 → 0. Проверены обработчики масштаба 1 → 2 → 1; это вызов реальных обработчиков, а не физический жест двумя пальцами. После закрытия число слайдов равно нулю. Процессы сохранялись, новых записей ApplicationExitInfo в этих чистых прогонах нет.

| Показатель | A35 | S25 Ultra |
| --- | ---: | ---: |
| Медиана native onDisplay для выбранного фото | 640 мс | 196 мс |
| Диапазон native onDisplay | 625–888 мс | 160–271 мс |
| PSS после 6 → 18 циклов | 994 → 973 MiB | 1261 → 1245 MiB |
| Native Heap после 6 → 18 циклов | 469 → 467 MiB | 472 → 471 MiB |
| PSS после RUNNING_LOW и GC | 900 MiB | 1180 MiB |

Время измерено от вызова штатного открытия до native onDisplay тестового фото; это не оценка всех сценариев интерфейса и не сравнение времени с прежним кодом. Общий PSS dev-сборки включает всё приложение и отладочную инфраструктуру. Снижение 23 → 3 относится к компонентам изображений, а не к проценту всей RAM.

На каждом устройстве production-резолвер обработал 160 тестовых защищённых вложений. Нативная расшифровка вернула файл, байты которого совпали с тестовым JPEG. Максимум активных загрузок — три, ready — 128, итоговые pending/active/queue — ноль. После очистки RAM последние восемь файлов открылись без новых скачиваний. Тестовые запросы направлялись временной подменой FileSystem в локальный сервер через USB; установочные credentials туда не передавались. Подмена восстанавливалась в finally. Для физического теста дедлайн уменьшался до 250 мс, сервер задерживал ответ на 2200 мс; получен timeout через 266/288 мс, поздняя публикация отсутствовала. Production-дедлайн 45 секунд проверен таймерами в автотесте.

Это не подтверждает прохождение настоящих медиа через удалённый API с VPN/без VPN. Сетевые настройки VPN не переключались; полная регрессия доставки/повторного подключения не входит в перечисленные доказательства.

## Подтверждение исправления по полным снимкам

После первых агрегированных замеров выявился рост JS примерно на 3 MiB за 15 дополнительных циклов. Первоначальный сбор полной кучи был отклонён автоматической проверкой из-за возможного содержимого переписки. Пользователь явно разрешил локальные снимки. Потоковый CDP обрывал большие ответы; временный локальный JSI-хук записал снимки прямо в приватный cacheDirectory, затем они были скопированы ADB в закрытые файлы /private/tmp. В Git и этот отчёт содержимое кучи не переносилось.

На обоих устройствах сделаны полные снимки до/после 15 циклов: до исправления цепочки, после патча AnimatedProps и после окончательного освобождения просмотрщика. PID сохранялись. Сравнение после патча и размонтирования просмотрщика:

| Изменение за 15 циклов | A35 до → после | S25 Ultra до → после |
| --- | ---: | ---: |
| AnimatedProps, количество | +436 → +4 | +436 → 0 |
| AnimatedMultiplication, количество | +477 → −5 | +447 → 0 |
| Environment, количество | +3733 → +21 | +3772 → −41 |
| Суммарный self_size в снимках | +3,53 → +0,33 MiB | +3,61 → +0,31 MiB |

Это изменение удержанных структур/служебных областей снимка, а не процент всей RAM приложения. Оставшаяся разница в основном приходится на буферы WeakRef/GC и профилировщика React DevTools. Полное отсутствие любых изменений памяти не заявляется. Доказанная длинная цепочка старых AnimatedProps и тысяч render-окружений устранена в проверенных циклах.

Исходный нативный файл RNSkManager.cpp восстановлен побайтно, SHA-256 `8215cad770ed91cac94128f9d45e63cf5d985dbc63631aac0cbf8e19cb70fd38`. Обычный dev APK пересобран и установлен на оба телефона. Проверено отсутствие диагностического хука, совпадение SHA-256 APK с локальным артефактом и нулевое число просмотрщиков после закрытия. SHA-256: `f57baa87ab410d1d9bbeef1a5bb7d7461848c734df911b0bb3ceba25d25efe76`. На каждом телефоне удалено 44 созданных тестовых файла, включая два приватных снимка; оба устройства возвращены на Home с нулевым playback owner и очищенным messageCache. Тест установки патча проверяет чистое применение, повторный postinstall и отказ при несовместимом/отсутствующем патче.

При перезагрузках dev runtime в 20:33 появились два нативных сбоя: A35 — assertion `Only one instance allowed` в HostTarget::registerInstance; S25 — `You attempted to access the app context before the module was created` при установке Expo JSI. Причина этих сбоев не исправлена в данной задаче. В чистых измеренных прогонах PID сохранялся. Эти сбои не выдаются за устранённые утечки чата.
