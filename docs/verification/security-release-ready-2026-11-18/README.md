# Подготовка безопасности к выпуску — 18 ноября 2026

Подготовительный backend развернут. Рабочие аккаунты, сообщения, покупки, Redis
и медиа не удалялись. Строгий новый старт **ещё не активирован**: сначала новая
Android-сборка должна стать доступна в Google Play. Несколько дней наблюдения
не заменяют это серверное переключение.

## Что выполнено

- Добавлена проверка квитанции сброса в MongoDB. При заданном `ACCOUNT_DATA_GENERATION`
  сервер не начинает принимать HTTP/Socket.IO, пока значение не совпадёт с квитанцией
  завершённой транзакции в этой БД. Ошибочный/преждевременный маркер не публикуется
  клиентам и не запускает очистку их локальных данных. Обычный совместимый запуск
  без маркера сохраняет прежнее поведение.
- На изолированном локальном replica set проверены настоящий скомпилированный сервер,
  транзакция сброса и десять сценариев. Включены доступ существующего legacy-аккаунта
  до переключения, отказ запуска с отсутствующей/неверной квитанцией, запрет старого
  клиента после переключения, создание пустого нового аккаунта, обязательность
  оригинального секрета, запрет его подмены и сохранение профиля после перезапуска.
- Рабочая БД `videochat` инвентаризирована без изменения данных. Неизвестных коллекций
  нет. На момент проверки: 924 пользователя, 908 установок, 1455 отдельных сообщений
  дружеских переписок, 13 записей покупок оформления и 1 запись платёжной покупки.
  Общий каталог Fliq и конфигурация выпуска сохраняются при будущем сбросе.
  Полный состав — [inventory.json](./inventory.json).
- На сервере подготовлены официальные MongoDB Database Tools 100.20.1 для Ubuntu 24.04.
  Проверена SHA-256 архива по официальным метаданным MongoDB. MongoDB Server не
  устанавливался и не обновлялся. [Результат](./backup-tools.json),
  [официальная инструкция](https://www.mongodb.com/docs/database-tools/installation/).
- В закрытом каталоге того же сервера созданы предварительные копии MongoDB,
  namespace `livi:*` в Redis, `.env` и 645 файлов медиа. Mongo-архив прочитан через
  `mongorestore --dryRun`. Это предварительная копия при работающем сервере:
  перед фактическим удалением требуется **новая копия после остановки писателей**.
  Проверка чтения архива не равна испытанию восстановления production-данных.
  Синтетическое восстановление ранее проверялось отдельно.
- Подготовлен и развернут проверенный backend-пакет с резервной копией исполняемого
  кода и автоматическим откатом при неуспешном запуске. До остановки не было участников
  LiveKit, очередей, пар или недавних незавершённых звонков. Зависимости, `.env`, pepper
  и действующий режим совместимости не менялись.
- После запуска повторно сверены все 225 файлов. `livi-backend` активен,
  `NRestarts=0`, MongoDB/Redis и Socket.IO Redis adapter готовы. `.env` — 0600.
- Рабочий API отклоняет запросы без авторизации, скрывает `.env` и debug route.
  Гостевой сокет остаётся без пользователя, получает отказ защищённого чтения/reauth
  и не получает приватных событий. Проверка не создавала аккаунты и не отправляла
  сообщений или звонков. [HTTP](./public-verification.json),
  [Socket.IO](./socket-negative.json).
- Production Android JS/Hermes export прошёл без создания AAB. Экспорт и backend-пакет
  проверены на буквальные значения настроенных локальных и production-секретов:
  совпадений нет. Production-секреты проверялись на сервере и не копировались с него.
  Это ограниченная проверка текущих значений, а не аттестация всей истории Git.

## Что сделать после доступности AAB в Google Play

Полный порядок — [план нового старта](../account-fresh-start-2026-11-17/README.md#порядок-production-переключения).
Для этого выпуска порядок следующий:

1. Собрать AAB с настоящей release-подписью, проверить доступность versionCode в Play
   (212 нельзя использовать повторно, если он уже загружен), опубликовать и убедиться,
   что пользователю действительно доступно обновление. QA `.dev` APK не публикуется.
2. Повторить read-only инвентаризацию и проверку активности. Зафиксировать точный состав
   удаления и выбранное поколение, например `fresh_20261118_1`. Этот пример сейчас не активирован.
3. Остановить backend и другие писатели. Сохранить текущую `.env` и сделать свежие
   проверенные резервные копии при остановленных писателях.
4. В конфигурации остановленного сервера установить `INSTALL_AUTH_MODE=strict`,
   `HTTP_INSTALL_SECRET_REQUIRED=1` и выбранный `ACCOUNT_DATA_GENERATION`.
   Не менять pepper и действующие ключи сервисов.
5. Запустить `scripts/reset-accounts.cjs --apply` с точными именем БД, маркером,
   подтверждением `<БД>:<маркер>` и абсолютным закрытым backup-dir. Скрипт повторно
   создаст/проверит архив и выполнит Mongo-транзакцию. При неизвестной коллекции — остановиться.
6. Удалить только `livi:*` через SCAN/UNLINK, убрать старые пользовательские медиа
   из публичного каталога в закрытую резервную папку. Общую Redis не очищать.
   Успешный Mongo-сброс не повторять с новым маркером ради обхода ошибки следующего шага.
7. Запустить backend, проверить совпадение квитанции/маркера, health, новый профиль,
   сохранение аккаунта после перезапуска, отказ отсутствующему/неверному секрету,
   старым клиентам и прежним URL медиа. Проверить отсутствие старых уведомлений/очередей.
8. Обновить публичную последнюю версию на реально опубликованный versionCode.
   После этого наблюдать несколько дней: Crashlytics/ANR, ошибки backend/авторизации,
   регистрацию, перезапуск, сообщения, звонки, VPN/переподключение и приглашение через Play.

Если Mongo-транзакция не завершилась, старую конфигурацию можно вернуть до запуска.
После завершённого сброса или появления новых пользователей нельзя произвольно менять
маркер либо восстанавливать старую БД: это отдельная операция с потерей новых данных.

## Зависимости и пределы проверки

Текущий `npm audit --omit=dev` для backend: **0 находок**.
Для frontend: 39 записей о пакетах (21 high, 18 moderate, 0 critical).
Это не 39 независимых ошибок: high-цепочка происходит от picomatch через Metro/Jest/Expo CLI.
В коде приложения не найдено импортов picomatch/micromatch/glob. Нельзя переносить оценку
Node-инструмента непосредственно на исполняемый код Android, но сам инструмент требует внимания.

Обновлённое 17.11.2026
[уведомление picomatch](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)
указывает отсутствие исправленной версии; последний опубликованный релиз — 4.0.7.
Принудительный `npm audit fix --force` предлагает смену Expo и не применялся.
Сборку выполнять из доверенного дерева без сторонних недоверенных glob-паттернов;
Metro не публиковать в интернет. Новая сборка потребует обычного физического прогона
именно подписанного артефакта/установки через Play.

Найденные moderate advisories и цепочки сохранены в
[dependency-audit.json](./dependency-audit.json). Замечания о начале анимации PiP,
реальной установке по приглашению через магазин и опубликованном AAB остаются в
[отчёте перед AAB](../pre-aab-212-2026-11-18/README.md).
Новая подготовка не добавляет E2EE для вложений: медиа по-прежнему доступны обладателю URL.

Исходные журналы и приватный JS export: `/private/tmp/livi-security-release-20261118/`.
Рабочие резервные копии остаются в закрытых каталогах сервера.
