# Текст и счётчик «Непрочитанных» после уведомления

Проверка 4 ноября 2026 года. Samsung A35 SM-A356E (`RFCX306PWLE`), Android 16.
VPN HIRO, Австрия. Проверялся пакет LiVi Dev; основной пакет не заменялся.

Причина: Android сохранял только ID отправителя. Строка строилась по unread,
а `selectChatPreviews` удалял неподтверждённое превью до ответа сервера.
В результате имя и бейдж уже отображались, а текст оставался пустым.

Исправление:

- Сервер учитывает unread перед доставкой сообщения. Socket, offline queue и push
  передают точный счётчик переписки; общий счётчик уведомления передаётся отдельно.
- Push содержит ID, отправителя, получателя, время, превью и счётчик одного сообщения.
  Короткий E2E-конверт передаётся зашифрованным и расшифровывается на устройстве.
  Конверт, превышающий бюджет FCM, не добавляется в payload; история загружается отдельно.
- Android сохраняет snapshot перед показом уведомления. Старый push не заменяет
  более новые текст/счётчик. JS подтверждает импорт конкретной версии, поэтому старый ack
  не удаляет новое уведомление. При миграции sender-only marker заменяется полными данными.
- Превью импортируется до публикации unread. Доставленному сообщению не требуется
  повторное подтверждение сервером. Неполные строки не показываются: для старого
  payload без текста предусмотрена загрузка до получения полных данных.
- Повторная доставка по push/socket не добавляет ещё одно непрочитанное. Версии
  запросов и время их начала защищают новый счётчик от запоздавшего ответа,
  включая ответ, полученный во время расшифровки push. Открытие чата очищает счётчик.

Автоматическая проверка: frontend — 109 наборов / 1088 тестов; backend — 31 набор /
307 тестов. TypeScript обеих частей, ESLint изменённых файлов и `git diff --check`
прошли. Android debug APK и 10 существующих native unit tests прошли.
Автономный release APK LiVi Dev / ARM64 собран с debug-подписью и установлен
с сохранением данных: `frontend/livi-unread-vpn-fix.apk`, версия 1.1.22 (209).
SHA-256: `858409f88ecdf4f5b689b3782f8e22beeedd46ea31572eca035b6b05f68a09f5`.

На телефоне использовались локально записанные тестовые push snapshot: сообщения
другим пользователям не отправлялись, production backend не изменялся.

| Сценарий | Результат |
| --- | --- |
| Обратный порядок push и устаревший ack | Более новое сообщение и счётчик 3 сохранены. |
| Возврат по уведомлению с VPN, Socket/HTTP чтение истории и unread намеренно задержаны | Строка содержит `LOCAL PREVIEW THREE` и бейдж 3. Ни одного кадра с одним именем без текста строки. |
| Холодный запуск, Wi-Fi и мобильная сеть временно отключены, Metro через USB | Первый видимый кадр строки содержит `LOCAL COLD PREVIEW FIVE` и 5. Перед запуском `pidof` был пуст. |
| Холодный запуск с активным VPN | Первый видимый кадр строки содержит тот же текст и 5; `pidof` перед запуском пуст. |

OCR видеозаписей и accessibility tree суммированы в
`verification/android-2026-11-04-unread/results.json`. Исходные записи и скриншоты:
`/private/tmp/livi-unread-device-evidence/`. Логи проверок: `/tmp/livi-unread-*`.

Границы проверки: реальные FCM с обновлённого backend ещё не отправлялись; backend
не развёрнут. В dev-сборке первый ряд при холодном запуске появился примерно через
10–12 секунд с начала записи; это время включает запуск приложения. При тёплом
возврате на записи есть краткое состояние пустого списка до импорта snapshot.
Проверка подтверждает совместное появление текста и счётчика самой строки,
но не мгновенный запуск всего экрана. Wi-Fi и мобильная сеть восстановлены,
VPN оставлен подключённым; синтетические pending-события и локальные значения
unread/cleared-chat после проверки восстановлены.
