# Отладка пушей входящего звонка в релизе

Когда получателю звонка не приходит уведомление (ни на заблокированном экране, ни поверх другого приложения).

## 1. Подготовка

- Телефон с **релизной** сборкой LiVi подключён к Mac по USB.
- На телефоне включена **отладка по USB** (Настройки → Для разработчиков → Отладка по USB).
- На Mac установлен `adb`: `brew install android-platform-tools` (если нет).

## 2. Захват логов на телефоне (получатель)

В терминале из папки `frontend`:

```bash
chmod +x scripts/capture-push-logs.sh
./scripts/capture-push-logs.sh
```

Скрипт очистит logcat и начнёт писать логи в файл `livi-push-debug-YYYYMMDD-HHMMSS.log` в текущей папке.

## 3. Воспроизведение

1. **Не останавливая скрипт**: на телефоне открой LiVi, затем сверни приложение (Home) или закрой из списка задач.
2. С **другого устройства** (или второго аккаунта) позвони этому пользователю (видеозвонок другу).
3. Подожди 10–15 секунд (звонок идёт, пуш должен уйти).
4. В терминале на Mac нажми **Ctrl+C** — запись логов остановится.

Логи сохранятся в `frontend/livi-push-debug-*.log` (и отфильтрованная копия в `livi-push-filtered-*.log`).

## 4. Что смотреть в логах

### На устройстве (получатель)

- **FCM/FirebaseMessaging** — доставка пуша на устройство. Если есть запись о получении сообщения в момент звонка — пуш до телефона дошёл, проблема в отображении/канале. Если записей нет — пуш до устройства не доходит (токен, сеть, backend).
- **ReactNativeJS** — логи из JS (наш `logger`). В релизе `EXPO_PUBLIC_LOG_LEVEL=warn`, поэтому видны только `[WARN]` и `[ERROR]`; строки с `[push]` могут быть только при ошибках (например, регистрация токена, обработка ответа).
- **expo / notification** — если expo-notifications что-то пишет в logcat при получении пуша.

### На backend (обязательно проверить)

Убедись, что при звонке **backend реально отправляет пуш**:

- В логах сервера при `call:initiate` должна быть отправка в Expo Push (без ошибок). Например, поиск по логам: `call:initiate`, `sendPushToUser`, `push`, `push-test`, ошибки от Expo/FCM.
- Если backend логирует ошибки при отправке пуша (invalid token, network, etc.) — причина на стороне сервера/токена.

Проверка на сервере (если есть доступ к логам):

```bash
# пример: смотреть логи сервиса в момент звонка
journalctl -u livi-backend -f | grep -E "call:initiate|push|sendPushToUser|Expo"
```

## 5. Типичные причины

| Симптом в логах | Возможная причина |
|-----------------|-------------------|
| Нет записей FCM о получении сообщения в момент звонка | Пуш не доходит до устройства: неверный/устаревший FCM-токен, backend не шлёт пуш, ошибка Expo Push API. Проверить backend-логи и что токен получателя актуален. |
| FCM сообщение есть, уведомления нет | Канал уведомлений «Звонки» отключён или заглушен пользователем; ограничения батареи/энергосбережения для приложения. |
| В backend ошибка при отправке пуша | Проверить FCM/Expo креды, формат payload, что для пользователя есть сохранённый push-токен в БД. |

## 6. Быстрая проверка без скрипта

Ручной захват в момент воспроизведения:

```bash
adb logcat -c && adb logcat -v time 2>&1 | tee livi-push-manual.log
```

Воспроизвести сценарий (свернуть приложение → звонок), затем Ctrl+C и поиск в `livi-push-manual.log` по словам: `FirebaseMessaging`, `FCM`, `push`, `notification`, `ReactNativeJS`, `[push]`.
