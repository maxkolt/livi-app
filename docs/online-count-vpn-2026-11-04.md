# Счётчик пользователей онлайн при VPN

Исправление во frontend, 4 ноября 2026 года.

Причины зависания: после первого неудачного HTTP-чтения повтор откладывался до
двух минут; снимки сокета отбрасывались во время UI-переходов; смена VPN-маршрута
не запускала отдельное обновление. Таймаут чтения также не ограничивал ожидание
тела ответа после получения HTTP-заголовков.

Теперь счётчик использует последний подтверждённый снимок при повторном открытии,
обновляется независимо через socket sync и HTTP, повторяет неудачные запросы
через 1/2/4/8/15/30 секунд. Каждый запрос ограничен 10 секундами вместе с чтением
тела; новый маршрут отменяет старую попытку и запускает обновление через 400 мс.
Поздний ответ со старого маршрута не применяется. Контрольное обновление — раз
в 30 секунд; подписки и таймеры удаляются при отключении хука.

Полученные socket-снимки не теряются во время UI-переходов. Счётчик исключает
текущего пользователя и дубликаты, а при смене аккаунта пересчитывается из полного
списка. До первого ответа показано «… пользователей онлайн»; ноль не подставляется
вместо отсутствующего ответа. При временном обрыве остаётся последнее подтверждённое
число, которое уточняется после восстановления связи.

Проверки: 112 frontend-наборов / 1112 тестов, TypeScript, ESLint изменённых файлов,
`git diff --check` — PASS. Новые тесты проверяют HTTP-ошибку при первом открытии,
зависшее тело ответа, игнорирование abort транспортом, смену VPN-маршрута,
поздние ответы, UI-переходы, переподключение, восстановление сети с недоступной
OS-проверкой интернета, смену пользователя, дедупликацию и отключение подписок.
Логи: `/tmp/livi-online-typecheck.log`, `/tmp/livi-online-frontend-tests.log`.

Новая сборка на телефоне не запускалась: пользователь собирает и проверяет её сам.
Backend для этого исправления не менялся; используются существующие `/api/presence`
и `presence:welcome:sync`. Без связи с сервером актуальное число неизвестно;
последний подтверждённый счётчик не является новым измерением.
